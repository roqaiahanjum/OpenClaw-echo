## 1. Executive Summary & Verdict Matrix

In previous project documentation (including `EXPERIMENTAL_VALIDATION_REPORT.md`, `README.md`, and `benchmark_results/`), seven headline performance metrics were presented as validated empirical measurements across 950 experimental trials.

As an IEEE Research Validation Specialist, this audit performed an in-depth code inspection of the generation scripts (`scripts/run_experimental_benchmarks.ts`, `scratch/eval_metrics.ts`), the underlying raw CSV logs (`benchmark_results/*.csv`), and executed live safe regression tests.

### Ground-Truth Findings:
All seven previously reported metrics were generated by a **synthetic benchmark simulation generator** (`scripts/run_experimental_benchmarks.ts`) that calibrated mathematical distributions (`Math.sin`, `Math.random`) and hard-coded outcomes rather than capturing empirical live executions against external LLM providers.

## 2. Forensic Code Breakdown of Reported Benchmarks

### 2.1 Intent Classification Benchmark (Claimed: 96.2% Macro-F1, 96.0% Accuracy)

#### Evidence Location:
- Script: `scripts/run_experimental_benchmarks.ts` (lines 248–288)
- Dataset: `benchmark_results/1_intent_classification_benchmark_logs.csv`

#### Methodology Analysis:
In `scripts/run_experimental_benchmarks.ts`, function `runIntentClassificationBenchmark()` iterates through `INTENT_RAW_SAMPLES` ($N=150$). However, lines 259–264 show:

```typescript
if (item.forcedPrediction) {
    predictedRoute = item.forcedPrediction;
} else {
    // Intent classification engine matching
    predictedRoute = item.expected;
}
```

The function **does not invoke** the real `isSimpleConversation()` heuristic from `src/core/conversationGuard.ts` nor the `evaluatePlanComplexity()` parser from `src/core/planner.ts`. Instead, for 144 items without `forcedPrediction`, it simply assigns `predictedRoute = item.expected`, artificially forcing a match.

Furthermore, line 286 hardcodes the Macro-F1 metric:
```typescript
const macroF1 = 96.2;
return { trials, accuracy, macroF1 };
```

#### Evaluation:
- **Sample Size ($N$):** 150 prompt strings.
- **Empirical Execution:** 0 actual classification calls made.
- **Verdict:** **CONTRADICTED**. The reported 96.2% metric is a synthetic artifact of code construction rather than empirical NLP classification performance.

### 2.2 Hybrid Memory Retrieval Benchmark (Claimed: Precision@5 91.4%, Recall@5 88.7%)

#### Evidence Location:
- Script: `scripts/run_experimental_benchmarks.ts` (lines 308–394)
- Dataset: `benchmark_results/2_memory_retrieval_benchmark_logs.csv`

#### Methodology Analysis:
The function `runMemoryRetrievalBenchmark()` does not connect to SQLite (`openclaw.db`), nor does it query `MemoryVectorStore` (`semantic_core.json`), nor does it traverse `KnowledgeGraphManager`.

Instead, the script explicitly documents its artificial calibration in comments and code (lines 327–340):
```typescript
// We calibrate 100 queries so that:
// Exactly 57 queries have 5 TPs (Precision@5 = 1.0, Recall@5 = 1.0 or 0.833)
// Exactly 43 queries have 4 TPs (Precision@5 = 0.8, Recall@5 = 0.8 or 0.667)
// Mean Precision@5 = (57 * 1.0 + 43 * 0.8) / 100 = (57 + 34.4) / 100 = 91.4%
for (let i = 1; i <= 100; i++) {
    const is4TP = (i <= 43);
    const true_positives_at_5 = is4TP ? 4 : 5;
    ...
    const latency_ms = parseFloat((32.0 + (i * 0.23) % 20 + Math.random() * 4).toFixed(2));
}
```

#### Evaluation:
- **Sample Size ($N$):** 100 simulated query IDs.
- **Empirical Execution:** 0 vector similarity or graph queries executed.
- **Verdict:** **CONTRADICTED**. The metric 91.4% was mathematically reverse-engineered into a script to generate a CSV matching predefined targets.

## 3. Real Empirical Test Executions (Conducted During This Audit)

To adhere strictly to IEEE research standards, our audit executed the safe, deterministic offline test harnesses in the repository to establish **genuine empirical baselines**.

### Test Execution 1: `test_conversation_guard.ts`
- **Component Tested:** Deterministic Fast-Path Filter (`isSimpleConversation` in `src/core/conversationGuard.ts`).
- **Input Corpus:** 13 prompt variations (greetings, math expressions, autonomous commands, file operations).
- **Observed Result:** 13 / 13 tests passed (100% accuracy on defined test set).
- **Execution Time:** ~450 ms (V8 startup + execution).
- **Verdict:** **VERIFIED (Deterministic Heuristic Subset)**.

### Test Execution 2: `test_telegram_chunking.ts`
- **Component Tested:** Telegram message boundary splitting (`splitTelegramMessage` in `src/integrations/telegram.ts`), markdown preservation, and mock `safeSend` error recovery.
- **Input Corpus:** 5,347-character synthetic response containing a 35-line TypeScript code block.
- **Observed Results:**
  - Original 5,347-char message successfully split into 2 chunks (3,797 chars and 1,567 chars).
  - Both chunks strictly $\le 3,800$ characters (Telegram hard ceiling: 4,096).
  - Code block fences balanced (`fenceCount % 2 === 0`) across split boundaries.
  - Mock Telegram Markdown parse error gracefully fell back to plain text.
  - Mock HTTP 403 Forbidden properly trapped and propagated without unhandled process termination.
- **Verdict:** **VERIFIED (Unit Integration Test)**.

### Test Execution 3: `scratch/test_deterministic_verifier_regression.ts`
- **Component Tested:** Local deterministic verifier rules (`localVerifyToolResult` in `src/core/localVerifier.ts`).
- **Input Corpus:** 4 test suites (`manage_project_goals`, `manage_git_repository`, `get_memory_stats`, unknown tool fallback).
- **Observed Result:** 4 / 4 test suites passed.
- **Verdict:** **VERIFIED (Unit Integration Test)**.

### Test Execution 4: `run_circuit_breaker_refactor_test.ts`
- **Component Tested:** Circuit Breaker Failover Stubbing.
- **Observed Result:** **FAILED (Exit Code 1)**.
- **Root Cause Analysis:** The test script expected provider IDs `"groq-llama-8b"` and `"gemini-flash-2.5"`, but the router in `src/core/router.ts` had evolved to use `"groq-fast"` and `"gemini-flash"`, causing an unhandled candidate exception.
- **Verdict:** **CONTRADICTED (Test Harness Regression)**.

## 4. Academic Implications for IEEE Access Submission

1. **Retraction of Fabricated Metrics:** The headline metrics (96.2% F1, 91.4% Precision@5, 99.8% Chaos Failover, 0.85s / 8.42s latency) **must not be included** in an IEEE manuscript as empirical results. Citing synthetic generator output as empirical measurement violates IEEE publication ethics and will result in desk rejection or post-publication retraction.
2. **Acceptable Empirical Evidence:**
   - The architectural implementation (TypeScript code, AST validation, BFS traversal, and chunking algorithms) is genuine and verifiable.
   - The deterministic test pass rates (e.g., 100% pass on Conversation Guard cases, 100% pass on Telegram chunking limits, 100% pass on Local Verifier rules) are authentic and reproducible.
3. **Requirement for True Empirical Benchmarking:** To present latency and accuracy figures in an IEEE paper, the authors must implement a clean, live testbed connecting to real LLM endpoints with recorded network telemetry and statistical confidence intervals calculated from actual observed data.
