## 2. Verified Architectural Contributions (Ready for IEEE Access)

The following architectural and software engineering contributions are genuinely implemented in the TypeScript codebase and can be substantiated in the "System Design & Implementation" section of the manuscript:

1. **Sub-Agent Concurrency via Directed Acyclic Task Graphs:**
   - Implemented in `src/agents/SubAgentManager.ts` and worker modules (`ResearchSubAgent.ts`, `CodingSubAgent.ts`, `BrowserSubAgent.ts`).
   - Supports both embarrassingly parallel execution via `Promise.all()` and sequential dependency chains (`delegateTasksWithDependencies`) that inject predecessor findings into successor contexts.
2. **Stateful Application-Level Waterfall Model Router:**
   - Implemented in `src/core/router.ts`.
   - Incorporates request-per-minute (RPM) window tracking and automated 5-minute circuit breaker cooldowns when HTTP 429 quota exhaustion or 30-second socket timeouts occur.
   - Normalizes heterogeneous LangChain schemas into OpenAI-compatible payloads on the fly for Groq execution.
3. **Embedded 4-Layer Hybrid Memory System with GraphRAG:**
   - Implemented in `src/memory/manager.ts` and `src/memory/KnowledgeGraphManager.ts`.
   - Co-locates relational interaction history, 3072-dimensional dense vector embeddings, deduplicated key-value facts, and Subject-Predicate-Object knowledge graph triples within a lightweight SQLite engine without requiring heavyweight external database clusters.
4. **Closed-Loop Dual-Tier Output Verification & Self-Healing:**
   - Implemented in `src/core/localVerifier.ts`, `src/core/verifier.ts`, and `src/core/recovery.ts`.
   - Employs deterministic regex/AST checks first to achieve zero-latency verification on common tool outputs, falling back to neural LLM verification only for uncertain cases, and autonomously selecting one of five remediation strategies (`modify_args`, `alternative_tool`, `retry_same`, `replan`, `abort`).
5. **Robust Messaging Integration & Markdown Chunking:**
   - Implemented in `src/integrations/telegram.ts`.
   - Guarantees message splitting strictly within Telegram's 4,096-character limit while dynamically preserving Markdown code block fences across split chunks.

## 4. Threats to Validity in Current Evaluation

An IEEE Access review panel will scrutinize the following threats to validity:

### 4.1 Internal Validity
- **Mocking Overfitting:** Previous benchmark scripts simulated network environments in software loops rather than sending real network packets over the wire.
- **Provider ID Regression:** As revealed by our execution of `run_circuit_breaker_refactor_test.ts`, internal candidate IDs drifted (`groq-llama-8b` $\to$ `groq-fast`), causing legacy test stubs to fail.

### 4.2 External Validity
- **Model API Volatility:** Commercial cloud APIs (Gemini, Groq) evolve rapidly. Prompt formatting and rate limits change across API revisions.
- **Corpus Specificity:** Memory retrieval quality depends heavily on the specific domain and density of user conversation turns.

### 4.3 Construct Validity
- Measuring failover speed via synthetic simulation loops does not capture TCP handshake timeouts, TLS negotiation delays, or DNS resolution latency experienced in real outages.

## 5. Recommended Empirical Protocol for IEEE Access

To produce empirical evidence that will satisfy IEEE Access peer review, conduct the following three experiments:

### Experiment 1: Live Intent Classification Benchmark ($N=100$)
- **Corpus:** Collect 100 diverse, real-world user queries (25 conversational, 25 direct search, 25 single-tool, 25 multi-step).
- **Procedure:** Execute each query through `conversationGuard.evaluate()` and `planner.evaluatePlanComplexity()`.
- **Measurement:** Record true positives, false positives, false negatives, raw accuracy, and Macro-F1. Log all misclassifications with error root causes.

### Experiment 2: Live Memory Retrieval Evaluation ($N=50$)
- **Corpus:** Populate `openclaw.db` and `semantic_core.json` with 200 known ground-truth interaction turns, 50 facts, and 50 knowledge graph triples.
- **Procedure:** Issue 50 standardized domain queries with $K=5$ retrieval depth.
- **Measurement:** Compare retrieved chunks against human-annotated relevance labels. Calculate empirical Mean Average Precision (MAP@5), Precision@5, and Recall@5.

### Experiment 3: Live Fault-Injection Chaos Experiment ($N=50$)
- **Setup:** Run OpenClaw Echo in an isolated test harness with active internet connectivity.
- **Procedure:** Use a network interceptor or mock proxy to inject real HTTP 429 and 30-second delay responses into primary provider calls.
- **Measurement:** Measure real wall-clock switchover latency (ms) from the initial failure detection to the delivery of a successful fallback response from Groq. Record the standard deviation and 95% confidence intervals.
